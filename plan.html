1. VSM の理解のすり合わせ

あなたの理解「プロセスを俯瞰して無駄や省略できるプロセスを確認できるもの」は本質を捉えています。 補足すると、VSM(Lean 由来、トヨタ生産方式 → 『Learning to See』)の肝は次の 3 点です。

  • 数値で無駄を可視化する: 各工程の「実作業時間 (Process Time)」と「待ち時間込みの経過時間 (Lead Time)」を並べ、作業していない時間 がどれだけあるかを見せる。多くの現場では Lead Time の 8〜9 割が待ち時間。
  • 品質の手戻りも無駄として扱う: 各工程の「一発で正しく完了する率 (%C&A: Percent Complete & Accurate)」を掛け合わせ、後工程で何割が手戻るかを見せる。
  • 現状 (Current State) と 改善後 (Future State) を比較する: 工程を省略・並列化・待ち時間短縮したときに、全体 Lead Time がどう変わるかを見て改善点 (Kaizen Burst ⚡) を決める。

2. 作るもの (MVP)

#機能内容
F1工程エディタ工程を表形式で追加・編集・並べ替え・削除。項目: 名前、担当、Process Time、Lead Time、%C&A、前工程からの待ち時間、メモ
F2VSM 図の自動生成入力から SVG を描画。工程ボックス、待ち時間の▲、下部のタイムラインはしご、顧客の入口/出口
F3サマリ指標Total LT / Total PT / Activity Ratio / Rolled %C&A をリアルタイム表示
F4無駄の自動ハイライト待ち時間比率が高い工程、%C&A が低い工程に ⚡(Kaizen Burst) を付与。しきい値は設定可
F5Future State シミュレーション各工程に「省略」「待ち時間を N% 削減」トグルを付け、Current vs Future の指標を並べて比較
F6保存 / 読込localStorage 自動保存、JSON エクスポート / インポート、SVG ダウンロード

MVP に 含めないもの: 情報フロー(電子/手書き矢印の区別)、複数ブランチ分岐、ドラッグでの自由配置、サーバ保存、複数ユーザ。

3. 技術構成

項目選択理由
ビルド / UIVite + React 18 + TypeScripthobby_list_web など既存プロジェクトと同じ構成
描画素の SVG を React で生成工程は横一列なのでレイアウト計算が単純。ライブラリ不要で軽い
スタイルCSS Modules(素の CSS)Chakra は今回不要。依存を減らす
テストVitest + @testing-library/react計算ロジックを red/green で先にテスト
状態管理useReducer + localStorage単一画面なので外部ライブラリ不要

データモデル

type ProcessStep = {
  id: string;
  name: string;
  owner?: string;
  processTime: number;   // 実作業時間
  leadTime: number;      // 経過時間 (processTime を含む)
  waitBefore: number;    // 前工程からこの工程が始まるまでの待ち
  percentCA: number;     // 0..100
  note?: string;
  // Future State 用
  skipped: boolean;
  waitReductionPct: number; // 0..100
};

type ValueStream = {
  title: string;
  unit: "h" | "d";
  steps: ProcessStep[];
  thresholds: { waitRatio: number; percentCA: number };
};

4. 実装ステップ (red/green)

Stepやることテスト
1Vite プロジェクト作成、Vitest 設定、空のテストが通ることを確認環境確認

5. 確認したいこと

  1. 時間の単位: 日 / 時間 の切替でよいか(デフォルトは「日」を想定)。
  2. 対象ドメイン: 初期サンプルはソフトウェア開発フローでよいか。製造系のサンプル(在庫数・段取り時間など)が必要なら項目を追加します。
  3. Future State の操作: 「省略」「待ち短縮 %」の 2 つで足りるか。他に「並列化」「PT 短縮」を入れるか。
  4. スタイル: 素の CSS で進めてよいか(Chakra UI を使いたければ切替可)。

特に指定がなければ上記のデフォルト(日 / ソフト開発サンプル / 2 操作 / 素の CSS)で進めます。
